## Test base classes
- Scope: Frappe v16.
- Fact: `frappe.tests.UnitTestCase` and `frappe.tests.IntegrationTestCase` (subclass of UnitTestCase) are the base classes. `frappe.tests.utils.FrappeTestCase` still exists as a compatibility copy but is marked `@deprecated` (since 2024-08, removal planned for v17) and warns on use.
- Correct approach: pure logic without DB -> `UnitTestCase`; anything touching the DB -> `IntegrationTestCase`. Do not write new tests on `FrappeTestCase`.
- Source: `frappe/tests/classes/{unit_test_case,integration_test_case}.py`, `frappe/deprecation_dumpster.py` (`get_tests_CompatFrappeTestCase`), `frappe/tests/utils/__init__.py`; wiki "Migrating to version 16".
- Local verification: verified in installed source.

## `bench run-tests` selection options
- Scope: Frappe v16.
- Fact: options are `--app`, `--doctype`, `--module-def`, `--module`, `--case`, `--test` (repeatable), `--doctype-list-path`, `--test-category unit|integration|all`, `--failfast`, `--junit-xml-output`, `--skip-before-tests`, `--debug`, `--profile`, `--coverage`, `--lightmode`. `--skip-test-records` is deprecated and does nothing (test records load lazily). The command refuses to run unless the site has `allow_tests` set (or env `CI`).
- Correct approach: run the narrowest selection (`--doctype`, `--module`, `--case`/`--test`), always with `--site`; never the whole app by default. Enabling `allow_tests` is a site-config change: ask first.
- Source: `frappe/commands/testing.py` (`run_tests`).
- Local verification: read from the click definition in installed source; command not executed.

## Desk routes
- Scope: Frappe v16.
- Fact: the Desk lives under `/desk/<doctype-slug>`; `/app`, `/app/...` and `/apps` redirect to `/desk...`.
- Correct approach: use `/desk/<slug>` (e.g. `/desk/<slug>/new`) for screenshots and links.
- Source: `frappe/hooks.py` (`website_redirects`, `app_home = "/desk/build"`).
- Local verification: verified in installed source.

## List view columns
- Scope: Frappe v16 Desk list view.
- Fact: columns are the title/subject column plus fields with `in_list_view` (in field order). If List View Settings has saved `fields` (or the settings dialog passes an override), `reorder_listview_fields` rebuilds the order from that list and fields missing from it are dropped. Saving through the list settings dialog writes an `in_list_view` Property Setter (`set_in_list_view_property`).
- Correct approach: for a column order change in app code, check the site's List View Settings first — it is site data and overrides the DocType order; a fixture/Property Setter may be needed instead of only editing DocType JSON.
- Source: `frappe/public/js/frappe/list/list_view.js` (`setup_columns`, `reorder_listview_fields`), `frappe/desk/doctype/list_view_settings/list_view_settings.py`.
- Local verification: verified by reading installed source (2026-11-24); not exercised in a browser.
