# Investigation Playbook

질문 하나에 근거 있는 답을 낸다. 프로덕션 코드는 바꾸지 않는다. 조사 완료는 변경 승인이 아니다.

## 언제 조사하나
- 조사: 새 Frappe 기능, 기억으로 확신할 수 없는 버전별 API·동작, 문서와 실제 동작이 다를 때, 원인 미확정 문제, 중요한 설계의 기술적 불확실성.
- 생략: DocType·Link 같은 안정된 기본 지식, 관련 파일 몇 개로 바로 답이 나오는 사실.

## 절차 (Main 직접 또는 읽기 전용 서브 에이전트)
1. 질문과 결정 목적을 한 줄로 적는다(이 답으로 무엇을 정하려는가).
2. 가장 싼 근거부터: 설치된 코드(`apps/<app>`)와 사이트 메타데이터 → 공식 문서 → 필요할 때만 격리 실험.
3. 격리 실험은 Test 사이트에서, 만든 데이터는 지운다. Dev·운영 데이터를 바꾸지 않는다.
4. 반례와 적용 범위(어느 버전·설정에서 사실인지)를 함께 본다.
5. 질문에 답할 만큼 근거가 모였거나, 더 조사할 가치가 낮으면 멈춘다.

## 보고 형식
```markdown
### 조사 결과
- 질문 / 목적:
- 결론: CONFIRMED | INCONCLUSIVE — 한 문장
- 근거: 코드 경로:줄, 실행한 명령과 출력 요약, 문서 링크
- 적용 범위: 확인한 버전·설정
- 반례·한계:
- 다음: (변경이 필요하면 Feature/Bug Fix/Upgrade로 별도 진행)
```
- 결론이 틀리면 영향이 큰 부분은 추가 검증을 권한다.
- 재사용할 가치가 있는 버전별 사실은 해당 `frappe-*` Skill에 적용 버전·근거와 함께 추가할지 Main이 판단한다(공통 Skill의 중대한 정책 변경은 사용자 승인).
